# Задание №2: Доступ к сети Интернет на ISP

Инструкция по настройке выхода в глобальную сеть Интернет на маршрутизаторе **ISP** с использованием пакетного фильтра **nftables** и динамической трансляции сетевых адресов и портов (NAPT / Masquerade).

> [!IMPORTANT] Место выполнения
> Все действия данного задания выполняются исключительно на виртуальной машине **ISP** (`isp.au-team.irpo`).

---

## Требования к заданию

1. **Маршрутизация**: включить пересылку пакетов IPv4 (`ip_forward`) на маршрутизаторе ISP.
2. **Внешний интерфейс**: интерфейс `enp7s1` подключён к магистральному провайдеру и получает адрес по DHCP.
3. **Трансляция портов (PAT / Masquerade)**: настроить динамическую трансляцию адресов в сторону глобальной сети через `nftables` для выхода внутренних офисов (HQ и BR) в Интернет.
4. **Автозагрузка**: обеспечить автоматический запуск и применение правил трансляции при загрузке системы.

---

## Шаг 1. Включение маршрутизации пакетов (IP Forwarding)

Чтобы маршрутизатор ISP пересылал пакеты между интерфейсами офисов (`enp7s2`, `enp7s3`) и внешним интерфейсом (`enp7s1`), необходимо активировать параметр ядра `net.ipv4.ip_forward`.

Откройте конфигурационный файл сетевой подсистемы:

```bash
vim /etc/net/sysctl.conf
```

Убедитесь в наличии строки или раскомментируйте её:

```text
net.ipv4.ip_forward = 1
```

::: tip Быстрая команда без редактора
```bash
echo "net.ipv4.ip_forward = 1" >> /etc/net/sysctl.conf
```
:::

Примените изменения перезапуском сетевой службы:

```bash
systemctl restart network
```

## Шаг 2. Установка и настройка nftables

В современных версиях ALT Linux для управления сетевой трансляцией (NAT) и фильтрацией используется **nftables**.

### 2.1. Установка пакетов

Обновите списки пакетов репозитория и установите `nftables` и удобный текстовый редактор:

```bash
apt-get update && apt-get install nftables nano -y
```

---

### 2.2. Создание файла конфигурации правил NAT

Создайте или отредактируйте конфигурационный файл правил `/etc/nftables/nftables.nft`:

```bash
nano /etc/nftables/nftables.nft
```

Внесите следующее содержимое:

```bash
#!/usr/sbin/nft -f

flush ruleset

table ip nat {
    chain postrouting {
        type nat hook postrouting priority srcnat;
        oifname "enp7s1" masquerade
    }
}
```

::: info Разбор конфигурации
* `flush ruleset` — очищает текущие правила перед загрузкой новых во избежание дублирования.
* `table ip nat` — создаёт таблицу трансляции для протокола IPv4.
* `chain postrouting` — цепочка пост-маршрутизации (срабатывает перед выходом пакета из сетевого интерфейса).
* `oifname "enp7s1" masquerade` — весь трафик, уходящий через внешний интерфейс `enp7s1` в сторону магистрального провайдера, подменяет свой исходящий IP-адрес на внешний адрес интерфейса (Masquerade).
:::

---

### 2.3. Применение правил и добавление в автозагрузку

Включите службу `nftables` в автозапуск при старте системы и примените сформированный набор правил:

```bash
# Включение и запуск службы nftables
systemctl enable --now nftables
systemctl start nftables

# Сброс старых правил и загрузка конфигурации из файла
nft flush ruleset
nft -f /etc/nftables/nftables.nft
```

---

## Шаг 3. Проверка работоспособности (Верификация)

Выполните команды проверки для подтверждения корректности настроек:

### 1. Проверка активных правил nftables

```bash
nft list ruleset
```

Ожидаемый вывод:
```text
table ip nat {
	chain postrouting {
		type nat hook postrouting priority srcnat; policy accept;
		oifname "enp7s1" masquerade
	}
}
```

---

### 2. Проверка включения пересылки пакетов ядра

```bash
sysctl net.ipv4.ip_forward
```

Ожидаемый результат:
```text
net.ipv4.ip_forward = 1
```

---

### 3. Проверка доступности внешней сети Интернет

Проверьте доступность внешнего ресурса отправкой ICMP-запросов (4 пакета):

```bash
ping -c4 ya.ru
```

Если пакеты успешно передаются и возвращаются (`0% packet loss`), то доступ к сети Интернет и разрешение имён на **ISP** функционируют штатно.
