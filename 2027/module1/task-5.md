# Задание №5: Безопасный удаленный доступ (SSH) (2027)

::: tip 📺 Видео-разбор задания
*В процессе разработки*
:::

В данном задании настраивается защита службы удалённого администрирования OpenSSH на серверах **HQ-SRV** и **BR-SRV**.

---

## 1. Теоретическая справка: безопасность OpenSSH в ALT Linux

::: info 📍 Особенность ALT Linux
В дистрибутивах ALT Linux конфигурационные файлы демона SSH расположены в каталоге `/etc/openssh/` (основной конфигурационный файл — `/etc/openssh/sshd_config`), в отличие от Debian/Ubuntu, где используется `/etc/ssh/`.
:::

### Разбор директив конфигурации `sshd_config`:
* **`Port 2027`** — смена стандартного порта (по умолчанию 22) на нестандартный порт года проведения чемпионата. Защищает сервис от фонового сканирования ботами в сети.
* **`AllowUsers sshuser`** — строгий белый список пользователей. Доступ разрешён исключительно пользователю `sshuser`. Попытка входа под `root` или любыми другими локальными пользователями будет отклонена ещё до проверки пароля.
* **`MaxAuthTries 2`** — максимальное количество попыток ввода неверного пароля в рамках одной сессии. Если пароль введён неверно 2 раза подряд, SSH-сервер принудительно разрывает соединение (защита от перебора паролей методом brute-force).
* **`Banner /etc/openssh/ssh_banner`** — путь к текстовому файлу, содержимое которого отображается клиенту до ввода пароля при подключении.

---

## Шаг 1. Настройка сервера главного офиса (HQ-SRV)

Выполните настройку под пользователем `root` на машине **HQ-SRV**:

### 1. Открываем конфигурационный файл демона SSH:
```bash
vim /etc/openssh/sshd_config
```

::: tip 💡 Памятка по работе в Vim
* Вход в режим редактирования: нажмите клавишу <kbd>i</kbd>.
* Выход в командный режим: нажмите <kbd>Esc</kbd>.
* Сохранить и выйти: введите `:wq` и нажмите <kbd>Enter</kbd> (или `:q!` для отмены и выхода без сохранения).
:::

Внесите или раскомментируйте следующие директивы:
```text
Port 2027
AllowUsers sshuser
MaxAuthTries 2
Banner /etc/openssh/ssh_banner
```

::: tip 💡 Как добавить директивы в конец файла без редактора
```bash
cat << 'EOF' >> /etc/openssh/sshd_config
Port 2027
AllowUsers sshuser
MaxAuthTries 2
Banner /etc/openssh/ssh_banner
EOF
```
:::

### 2. Создаем файл баннера и перезапускаем службу:
```bash
# Создаем файл баннера с текстом предупреждения:
echo "Authorized access only" | tee /etc/openssh/ssh_banner

# Перезапускаем демон OpenSSH для применения параметров:
systemctl restart sshd
```

---

## Шаг 2. Настройка сервера филиала (BR-SRV)

На сервере **BR-SRV** выполняются аналогичные действия под `root`:

```bash
# 1. Добавляем параметры в конфигурационный файл:
cat << 'EOF' >> /etc/openssh/sshd_config
Port 2027
AllowUsers sshuser
MaxAuthTries 2
Banner /etc/openssh/ssh_banner
EOF

# 2. Создаем файл баннера:
echo "Authorized access only" | tee /etc/openssh/ssh_banner

# 3. Перезапускаем службу OpenSSH:
systemctl restart sshd
```

---

## Шаг 3. Проверка работоспособности (Верификация)

Для проверки подключаемся с соседних узлов, указав нестандартный порт подключения через ключ `-p`:

### 1. Проверка HQ-SRV с маршрутизатора HQ-RTR:
Перейдите в консоль **HQ-RTR** и выполните команду подключения:
```bash
ssh -p 2027 sshuser@192.168.100.2
```

**Что должно произойти:**
1. На экране отобразится строка баннера:
   ```text
   Authorized access only
   ```
2. Появится запрос пароля (`sshuser@192.168.100.2's password:`).
3. Введите пароль `P@ssw0rd` — сессия успешно откроется.
4. Выйдите из сессии командой:
   ```bash
   exit
   ```

---

### 2. Проверка BR-SRV с межсетевого экрана BR-FW:
Перейдите в консоль **BR-FW** и подключитесь к локальному серверу филиала:
```bash
ssh -p 2027 sshuser@172.16.20.2
```

**Что должно произойти:**
1. Отображается предупреждение `Authorized access only`.
2. После ввода пароля `P@ssw0rd` вход выполняется успешно.
3. Завершите сеанс командой:
   ```bash
   exit
   ```

---

### 3. Проверка критериев безопасности (Негативные тесты):

* **Подключение без указания порта (порт 22 по умолчанию):**
  ```bash
  ssh sshuser@192.168.100.2
  ```
  *Должна вернуться ошибка:* `ssh: connect to host 192.168.100.2 port 22: Connection refused` *(порт 22 закрыт).*

* **Попытка входа под пользователем `root`:**
  ```bash
  ssh -p 2027 root@192.168.100.2
  ```
  *Сервер должен сразу отказать в доступе:* `Permission denied, please try again.`

## ⚡ Шпаргалка для быстрого выполнения на экзамене

Выполняется одинаково на **HQ-SRV** и **BR-SRV**:

```bash
cat << 'EOF' >> /etc/openssh/sshd_config
Port 2027
AllowUsers sshuser
MaxAuthTries 2
Banner /etc/openssh/ssh_banner
EOF

echo "Authorized access only" | tee /etc/openssh/ssh_banner
systemctl restart sshd
```
