# Задание №3: Сервер сетевой файловой системы (NFS) на HQ-SRV

::: tip 📺 Видео-разбор задания
*В процессе разработки*
:::

В данном задании настраивается служба сетевой файловой системы (**NFS** — Network File System) на сервере главного офиса **HQ-SRV** для предоставления общего сетевого дискового ресурса на клиентскую рабочую станцию **HQ-CLI**.

---

## Требования задания:
* В качестве папки общего доступа выбрать каталог **`/raid/nfs`** (расположенный на RAID-массиве, настроенном в Задании №2);
* Доступ для чтения и записи предоставить **исключительно для сети в сторону HQ-CLI** (`192.168.200.0/28`);
* На рабочей станции **`HQ-CLI`** настроить постоянное автомонтирование сетевого каталога в папку **`/mnt/nfs`**;
* Основные параметры сервера и статус экспорта зафиксировать в отчёте.

---

## Теоретическая справка: как работает NFS и параметры экспорта

1. **Что такое NFS (Network File System)?**  
   NFS — это протокол сетевого доступа к файловым системам, позволяющий клиентским компьютерам прозрачно монтировать каталоги удалённого сервера через сеть, работая с ними так же быстро и удобно, как с локальными дисками.
2. **Параметры директивы экспорта (`/etc/exports`):**
   * **`rw`** (*read-write*) — разрешает клиентам как чтение, так и запись новых/существующих файлов.
   * **`no_subtree_check`** — отключает проверку поддеревьев каталогов. Значительно ускоряет передачу файлов и предотвращает сбои при переименовании открытых файлов.
   * **`no_root_squash`** — по умолчанию NFS преобразует запросы от пользователя `root` на клиенте в непривилегированного пользователя `nobody`/`nogroup` (*root squashing* в целях безопасности). Опция `no_root_squash` отключает это ограничение, позволяя суперпользователю клиента управлять файлами от имени `root`.
3. **Параметры монтирования на клиенте (`/etc/fstab`):**
   * **`_netdev`** — критически важная опция для сетевых файловых систем. Указывает системе инициализации монтировать данный ресурс только **после** полной инициализации и поднятия сетевых интерфейсов, предотвращая зависание системы при загрузке.
   * **`soft`** — если NFS-сервер временно недоступен, клиент после нескольких попыток вернёт ошибку ввода-вывода (I/O error), а не зависнет намертво в ожидании ответа (в отличие от опции `hard`).

## Часть 1. Настройка NFS-сервера на HQ-SRV

::: info 📍 Место выполнения
Все действия Части 1 выполняются под пользователем **`root`** на сервере **HQ-SRV** (`192.168.100.2`).
:::

### Шаг 1. Установка пакетов сервера NFS

Обновляем локальный индекс репозиториев и устанавливаем демон NFS-сервера и служебные утилиты:

```bash
apt-get update && apt-get install nfs-server nfs-utils -y
```

---

### Шаг 2. Создание каталога общего доступа и выставление прав

Сетевой каталог создаётся внутри примонтированного в Задании №2 массива `/raid`:

```bash
# Создаём целевую директорию nfs
mkdir /raid/nfs

# Выставляем полные права доступа для всех пользователей
chmod 777 /raid/nfs
```

---

### Шаг 3. Настройка файла экспорта /etc/exports

Ограничиваем сетевой доступ к каталогу исключительно подсетью клиентов главного офиса **`192.168.200.0/28`** (VLAN 200, в которой находится `HQ-CLI`):

```bash
# Создаём резервную копию конфигурационного файла
cp /etc/exports /etc/exports.back

# Добавляем запись экспорта каталога для сети HQ-CLI
echo "/raid/nfs 192.168.200.0/28(rw,no_subtree_check,no_root_squash)" >> /etc/exports
```

---

### Шаг 4. Запуск и активация службы nfs-server

Включаем автоматический запуск демона при старте ОС и немедленно запускаем службу:

```bash
# Включаем автозапуск и активируем службу NFS-сервера
systemctl enable --now nfs-server

# Проверяем статус работы демона
systemctl status nfs-server
```

Проверяем список активных экспортных записей сервера командой `exportfs`:

```bash
exportfs -v
```

**Пример корректного вывода:**
```text
/raid/nfs  192.168.200.0/28(rw,wdelay,no_root_squash,no_subtree_check,sec=sys,rw,secure,no_root_squash,no_all_squash)
```

::: tip 💡 Обновление экспорта без перезапуска
Если в будущем потребуется изменить записи в `/etc/exports`, службу перезапускать не обязательно — достаточно выполнить команду:
```bash
exportfs -ra
```
:::

## Часть 2. Настройка клиента на рабочей станции HQ-CLI

::: info 📍 Место выполнения
Все действия Части 2 выполняются на рабочей станции **HQ-CLI** под пользователем с привилегиями `root` (или через `sudo`).
:::

### Шаг 5. Создание локальной точки монтирования

Создаём каталог монтирования на клиенте и задаём открытые права:

```bash
# Создаём каталог монтирования
mkdir /mnt/nfs

# Устанавливаем полные права доступа на точку монтирования
chmod -R 777 /mnt/nfs
```

---

### Шаг 6. Проверка доступности экспорта с сервера

С помощью утилиты `showmount` опрашиваем NFS-сервер `HQ-SRV` по его IP-адресу (`192.168.100.2`):

```bash
showmount -e 192.168.100.2
```

**Пример корректного ответа:**
```text
Export list for 192.168.100.2:
/raid/nfs 192.168.200.0/28
```

> **Примечание:** Если экспортный список отображается, значит сетевая связность присутствует, правила межсетевого экрана не блокируют трафик, а служба NFS на сервере успешно отдаёт список шар.

---

### Шаг 7. Настройка постоянного автомонтирования в /etc/fstab

Чтобы сетевая папка автоматически монтировалась при каждом включении или перезагрузке машины, вносим запись в файл `/etc/fstab`:

```bash
# Создаём резервную копию системного файла fstab
cp /etc/fstab /etc/fstab.back

# Добавляем строку монтирования сетевого ресурса NFS
echo "192.168.100.2:/raid/nfs /mnt/nfs nfs rw,soft,_netdev 0 0" >> /etc/fstab
```

**Разбор параметров строки монтирования:**
* `192.168.100.2:/raid/nfs` — адрес NFS-сервера и путь к экспортируемому каталогу на стороне сервера.
* `/mnt/nfs` — локальная точка монтирования на клиенте.
* `nfs` — тип сетевой файловой системы.
* `rw,soft,_netdev` — параметры монтирования (чтение/запись, мягкое прерывание при недоступности, ожидание сети перед монтированием).
* `0 0` — отключение создания дампа архивации (`dump`) и порядка проверки диска (`fsck`).

---

### Шаг 8. Применение монтирования и проверка тома

Применяем изменения без перезагрузки рабочей станции:

```bash
# Применяем монтирование всех файловых систем
mount -av
```

В выводе команды должна появиться строка:
```text
/mnt/nfs                 : successfully mounted
```

Проверяем тип файловой системы и объём смонтированного ресурса:

```bash
df -T /mnt/nfs
```

**Пример корректного вывода:**
```text
Filesystem              Type  1K-blocks  Used  Available Use%  Mounted on
192.168.100.2:/raid/nfs nfs     2030488    48    1909856   1%  /mnt/nfs
```

## Часть 3. Тестирование работоспособности

Проверяем совместный доступ и возможность создания файлов из клиентской операционной системы.

### 1. Создание тестового файла на HQ-CLI:

```bash
touch /mnt/nfs/test_file
ls -l /mnt/nfs/test_file
```

**Вывод:**
```text
-rw-r--r-- 1 root root 0 Sep 28 22:38 /mnt/nfs/test_file
```

### 2. Проверка наличия файла на сервере HQ-SRV:

Переходим в терминал **HQ-SRV** и проверяем локальный каталог `/raid/nfs`:

```bash
ls -l /raid/nfs
```

**Вывод:**
```text
-rw-r--r-- 1 root root 0 Sep 28 22:38 test_file
```

Файл мгновенно отображается на сервере, что подтверждает полную работоспособность протокола NFS, корректность сетевых настроек и прав на запись!
