# Задание №1: Контроллер домена Samba DC на сервере BR-SRV

::: tip 📺 Видео-разбор задания
*В процессе разработки*
:::

В данном задании настраивается служба каталога **Active Directory** на базе **Samba DC** на сервере филиала **BR-SRV**, выполняется ввод клиентской рабочей станции **HQ-CLI** в созданный домен, настраиваются пользователи, группы, парольные политики и строго ограниченные привилегии `sudo`.

---

## Требования задания:
1. **Настройка контроллера домена Samba DC на сервере BR-SRV**:
   * Ввести в созданный домен машину **HQ-CLI**;
   * Создать **5 пользователей** для офиса HQ: имена пользователей формата `hquser№` (`hquser1`, `hquser2`, `hquser3`, `hquser4`, `hquser5`);
   * **Политика паролей**:
     * Минимальная длина пароля: **8 символов**;
     * Блокировка учётной записи после **5 неудачных попыток** входа;
   * Создать группу **`hq`**, включить в неё всех созданных пользователей;
   * Убедиться, что пользователи группы `hq` имеют право аутентифицироваться на **HQ-CLI**;
   * Пользователи группы `hq` должны иметь возможность повышать привилегии через `sudo` **исключительно** для выполнения ограниченного набора команд: **`cat`**, **`grep`**, **`id`**. Запускать любые другие команды с повышенными привилегиями пользователи группы права не имеют.

---

## Шаг 1. Настройка DNS на HQ-CLI

Для успешного ввода рабочей станции в домен Active Directory машина должна обращаться к контроллеру домена как к первичному DNS-серверу.

1. В графической оболочке **HQ-CLI** открываем терминал и переходим в режим суперпользователя:
   ```bash
   su -
   ```
   *(вводим пароль от root: `toor`)*

2. Модифицируем файл `/etc/net/ifaces/ens18/resolv.conf`:
   ```bash
   nano /etc/net/ifaces/ens18/resolv.conf
   ```
   Прописываем две записи DNS (первичный — Samba DC на `BR-SRV`, вторичный — корпоративный DNS на `HQ-SRV`):
   ```text
   nameserver 172.16.20.2
   nameserver 192.168.100.2
   ```
   > *Если эти записи уже присутствуют в файле, переходите к пункту 4.*

3. Перезагружаем **HQ-CLI** командой `reboot`:
   ```bash
   reboot
   ```

4. После перезагрузки проверяем итоговую конфигурацию резолвера:
   ```bash
   cat /etc/resolv.conf
   ```

   **Ожидаемый вывод:**
   ```text
   search au-team.irpo
   nameserver 172.16.20.2
   nameserver 192.168.100.2
   ```

   ![Проверка /etc/resolv.conf](/images/2027/m2-t1-resolv-conf.png)

## Шаг 3. Создание пользователей и настройка политик на BR-SRV

Все команды данного шага выполняются под пользователем `root` на сервере **BR-SRV** (`br-srv.au-team.irpo`).

### 1. Создаем 5 пользователей
```bash
samba-tool user add hquser1 P@ssw0rd
samba-tool user add hquser2 P@ssw0rd
samba-tool user add hquser3 P@ssw0rd
samba-tool user add hquser4 P@ssw0rd
samba-tool user add hquser5 P@ssw0rd
```

::: tip 💡 Создание пользователей в одну строку (циклом Bash)
```bash
for i in {1..5}; do samba-tool user add hquser$i P@ssw0rd; done
```
:::

![Создание пользователей](/images/2027/m2-t1-users-add.png)

---

### 2. Задаем минимальную длину пароля в 8 символов
```bash
samba-tool domain passwordsettings set --min-pwd-length=8
```
![Настройка длины пароля](/images/2027/m2-t1-pwd-length.png)

---

### 3. Настройка опций блокировки учетной записи
```bash
samba-tool domain passwordsettings set \
--account-lockout-threshold=5 \
--account-lockout-duration=5 \
--reset-account-lockout-after=15
```

#### 🔍 Разбор параметров:
* **`--account-lockout-threshold=5`** — количество неудачных попыток ввода пароля подряд, после которых аккаунт блокируется.
* **`--account-lockout-duration=5`** — продолжительность блокировки в минутах.
* **`--reset-account-lockout-after=15`** — интервал в минутах, по истечении которого счётчик неудачных попыток сбрасывается в 0.

![Настройка блокировки аккаунта](/images/2027/m2-t1-lockout.png)

---

### 4. Проверяем текущие настройки парольной политики домена
```bash
samba-tool domain passwordsettings show
```
![Проверка параметров passwordsettings](/images/2027/m2-t1-pwd-show.png)

---

### 5. Создаем группу `hq` и добавляем в неё пользователей
```bash
# 1. Создаем доменную группу:
samba-tool group add hq

# 2. Добавляем всех 5 пользователей в группу hq:
samba-tool group addmembers hq hquser1,hquser2,hquser3,hquser4,hquser5
```

::: tip 💡 Добавление пользователей в группу одной командой
```bash
for i in {1..5}; do samba-tool group addmembers hq hquser$i; done
```
:::

![Создание группы и добавление участников](/images/2027/m2-t1-group-add.png)

---

### 6. Проверяем список пользователей и участников группы
```bash
# Просмотр всех учетных записей домена:
samba-tool user list

# Просмотр состава группы hq:
samba-tool group listmembers hq
```
![Вывод списка пользователей и участников группы](/images/2027/m2-t1-listmembers.png)

## Шаг 4. Настройка ограниченных привилегий sudo на HQ-CLI

::: info 📍 Место выполнения
Команды данного шага выполняются на клиентской машине **HQ-CLI** под пользователем **`root`**.
:::

1. Открываем терминал и переходим в режим суперпользователя:
   ```bash
   su -
   ```

2. Выполняем связывание ролей и настройку прав:
   ```bash
   # 1. Проверяем статус подсистемы сопоставления ролей libnss-role:
   control libnss-role
   # Ожидаемый вывод: enabled

   # 2. Связываем доменную группу hq с привилегированной системной ролью wheel:
   roleadd hq wheel

   # 3. Добавляем правило строго ограниченного sudo в конец файла /etc/sudoers:
   echo "WHEEL_USERS ALL=(ALL:ALL) /bin/cat, /bin/grep, /usr/bin/id" >> /etc/sudoers

   # 4. Проверяем корректность внесённой записи:
   tail -n 3 /etc/sudoers
   ```

---

### 2. Проверка разрешённых команд sudo
Открываем терминал под пользователем `hquser1` и выполняем разрешённые команды:
```bash
# 1. Проверка идентификатора суперпользователя:
sudo id
# Вводим пароль пользователя: P@ssw0rd
# Ожидаемый вывод: uid=0(root) gid=0(root) groups=0(root)...

# 2. Чтение файла через cat:
sudo cat /etc/resolv.conf

# 3. Поиск по файлу через grep:
sudo grep "nameserver" /etc/resolv.conf
```
![Успешный запуск разрешенных команд](/images/2027/m2-t1-sudo-allowed.png)
