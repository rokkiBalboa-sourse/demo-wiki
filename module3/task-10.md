# Задание №10: Резервное копирование данных HQ-SRV на узел хранения HQ-CLI

В данном задании на сервере главного офиса (**HQ-SRV**) развёртывается сервер управления резервным копированием отечественного программного комплекса **«Кибер Бэкап»** (версия 17.4 или аналог) со встроенной защитой от вирусов-вымогателей (Active Protection).

На сервере настраивается организация **`irpo`** и администратор **`irpoadmin`** с паролем **`P@ssw0rd`**. На клиентской рабочей станции **HQ-CLI** устанавливается агент с функциями узла хранилища (Storage Node), создаётся каталог **`/backup`**, после чего настраиваются и успешно выполняются два плана резервного копирования данных сервера **HQ-SRV** (директория `/etc` и база данных MySQL `webdb`).

> [!IMPORTANT] Где выполнять
> 1. **HQ-SRV** — установка сервера управления «Кибер Бэкап», создание организации, администратора и планов резервного копирования.
> 2. **HQ-CLI** — установка агента узла хранилища (Storage Node), создание папки `/backup` и приём резервных копий.

---

## 1. Теоретическая справка: архитектура комплекса «Кибер Бэкап»

Комплекс «Кибер Бэкап» состоит из нескольких взаимодействующих компонентов:
* **Сервер управления (Management Server)** — центральный узел координации, хранения политик, расписаний и веб-консоли (по умолчанию порт `https://<IP>:9877`).
* **Узел хранилища (Storage Node)** — служба, управляющая устройствами хранения (директории на дисках, сетевые хранилища, ленточные библиотеки).
* **Агент резервного копирования (Backup Agent)** — модуль, непосредственно выполняющий чтение файлов, создание моментальных снимков и инкрементов на защищаемом сервере.
* **Модуль защиты от программ-вымогателей (Active Protection)** — эвристический анализ поведения процессов для предотвращения несанкционированного шифрования файлов.

## 3. Развёртывание сервера управления на сервере HQ-SRV

Выполните действия под пользователем `root` на сервере **HQ-SRV**:

### Шаг 1. Монтирование дистрибутива и запуск установщика

Пакеты инсталлятора находятся на подключаемом диске `Additional.iso`:

```bash
mkdir -p /mnt/iso
mount /dev/sr0 /mnt/iso 2>/dev/null || mount /dev/cdrom /mnt/iso 2>/dev/null

# Переходим в директорию с установщиком Кибер Бэкап:
cd /mnt/iso/backup/ 2>/dev/null || cd /mnt/iso/
ls -la
```

Запускаем мастер установки в автоматическом или консольном режиме:

```bash
./CyberBackup_17.4_x86_64.bin -a
```

В мастере установки выбираем:
* **Компоненты для установки**: Сервер управления (Management Server) и Агент для Linux (Agent for Linux).

---

### Шаг 2. Создание системного пользователя irpoadmin

Для входа в панель управления сервером создаём пользователя `irpoadmin` и назначаем пароль:

```bash
useradd -m -s /bin/bash irpoadmin
echo "irpoadmin:P@ssw0rd" | chpasswd

# Добавляем пользователя в группу администраторов резервного копирования:
usermod -aG wheel,acronis,cyberbackup irpoadmin 2>/dev/null
```

---

## 4. Развёртывание узла хранилища на рабочей станции HQ-CLI

Переходим на клиентскую рабочую станцию **HQ-CLI** под пользователем `root`:

### Шаг 1. Подготовка каталога хранения /backup
```bash
mkdir -p /backup
chmod 777 /backup
```

### Шаг 2. Установка Агента и Узла хранилища
Монтируем образ `Additional.iso` на HQ-CLI и запускаем установщик:

```bash
mkdir -p /mnt/iso
mount /dev/sr0 /mnt/iso 2>/dev/null || mount /dev/cdrom /mnt/iso 2>/dev/null
cd /mnt/iso/backup/ 2>/dev/null || cd /mnt/iso/

./CyberBackup_17.4_x86_64.bin -a
```

В мастере установки выбираем:
* **Компоненты**: **Узел хранилища (Storage Node)** и **Агент для Linux**.
* **Регистрация на сервере управления**:
  * Адрес сервера управления: `192.168.1.10` (HQ-SRV).
  * Порт: `9877`.
  * Учётные данные администратора: логин `irpoadmin`, пароль `P@ssw0rd` (или `root` / `P@ssw0rd`).

---

## 5. Настройка организации, хранилища и планов в веб-интерфейсе

На рабочей станции **HQ-CLI** откройте браузер и перейдите в веб-консоль управления:

```text
https://192.168.1.10:9877
```

1. **Авторизация**:
   * Имя пользователя: `irpoadmin`
   * Пароль: `P@ssw0rd`

2. **Настройка организации**:
   * Перейдите в раздел **«Настройки»** → **«Организации»** (или при первичном мастере быстрой настройки).
   * Задайте имя организации: **`irpo`**.

3. **Добавление хранилища на HQ-CLI**:
   * Перейдите в меню **«Хранилища резервных копий»** → **«Добавить хранилище»**.
   * Тип хранилища: **«Узел хранилища»** (`HQ-CLI`).
   * Путь к каталогу: **`/backup`**.
   * Сохраните созданное расположение хранилища.

## 6. Создание и запуск планов резервного копирования

### План №1. Резервное копирование директории /etc
1. В веб-панели перейдите в раздел **«Устройства»** → выберите сервер **`HQ-SRV`** → нажмите **«Защитить»** (Создать план резервного копирования).
2. **Что копировать**: выберите **«Файлы/папки»**.
3. Укажите путь: каталог **`/etc`** (включая все вложенные папки и файлы).
4. **Куда копировать**: выберите узел хранилища **`HQ-CLI`** (`/backup`).
5. **Имя плана**: `Backup_ETC`.
6. Нажмите **«Создать»** и затем кнопку **«Запустить сейчас»**.

---

### План №2. Резервное копирование базы данных webdb (MySQL/MariaDB)
1. Выберите сервер **`HQ-SRV`** → нажмите **«Защитить»** (Создать новый план).
2. **Что копировать**: выберите **«Базы данных MySQL / MariaDB»** (или режим резервного копирования каталога баз данных / файлов дампа).
3. Выберите базу данных: **`webdb`**.
4. **Куда копировать**: выберите узел хранилища **`HQ-CLI`** (`/backup`).
5. **Имя плана**: `Backup_WebDB`.
6. Нажмите **«Создать»** и затем **«Запустить сейчас»**.

---

## 7. Проверка результатов выполнения

1. **В веб-консоли**:
   * Перейдите в раздел **«Действия»** / **«Журнал операций»**.
   * Оба задания резервного копирования (`Backup_ETC` и `Backup_WebDB`) должны завершиться со статусом **«Успешно»** (зелёная галочка).

2. **В файловой системе на HQ-CLI**:
   Откройте терминал на машине **HQ-CLI** и проверьте каталог `/backup`:
   ```bash
   ls -lh /backup/
   ```
   В директории должны находиться созданные файлы архивных резервных копий (с расширением `.tibx` или аналогичным).
