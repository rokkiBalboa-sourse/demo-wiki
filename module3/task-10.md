# Задание №10: Резервное копирование данных HQ-SRV на узел хранения HQ-CLI

В данном задании на сервере главного офиса (**HQ-SRV**) развёртывается сервер управления отечественной системы резервного копирования **«Кибер Бэкап»** (версия 17.4) со встроенным агентом для Linux и модулем резервного копирования СУБД MySQL/MariaDB. 

На клиентской машине (**HQ-CLI**) устанавливается **Узел хранения (Storage Node)**. В веб-консоли создаётся организация **`irpo`**, учетная запись администратора **`irpoadmin`** (`P@ssw0rd`), настраивается хранилище **`backup_dir`** в каталоге `/backup` и выполняются два плана резервного копирования: системной директории `/etc` (**`etc_backup`**) и базы данных MariaDB (**`webdb_backup`**).

> [!IMPORTANT] Где выполнять
> 1. **HQ-SRV** — обновление ядра, установка сервера управления «Кибер Бэкап» и агентов, создание пользователя `irpoadmin`, включение MariaDB.
> 2. **HQ-CLI** — обновление ядра, установка узла хранения (Storage Node) с привязкой к `192.168.1.10`, создание планов и запуск бэкапов через веб-интерфейс.

---

## 1. Памятка по работе в Vim

::: tip Памятка по работе в Vim
* **Вход в режим редактирования**: нажмите клавишу `i`.
* **Выход в командный режим**: нажмите `Esc`.
* **Сохранить и выйти**: введите `:wq` и нажмите `Enter` (или `:q!` для отмены и выхода без сохранения).
:::

---

## 2. Подготовка и установка Кибер Бэкап на сервере HQ-SRV

Выполните действия под пользователем `root` на сервере **HQ-SRV**:

### Шаг 1. Отключение монтирования /raid (для исключения конфликтов)

Открываем `/etc/fstab` в редакторе `vim`:

```bash
vim /etc/fstab
```

Удаляем последнюю строку с точкой монтирования `/raid` (в командном режиме нажимаем `dd`).

Сохраняем файл (`Esc` → `:wq` → `Enter`).

---

### Шаг 2. Установка сборочных заголовков и обновление ядра

Для сборки модулей ядра `snapapi` (создание снимков дисков) требуется актуальное ядро и заголовки:

```bash
apt-get update && apt-get install kernel-source-6.1 kernel-headers-modules-un-def gcc make kmod-sign -y

update-kernel -y

reboot
```

После перезагрузки проверяем версию загруженного ядра:

```bash
uname -r
```

---

### Шаг 3. Создание пользователя irpoadmin

Создаём пользователя согласно заданию:

```bash
useradd irpoadmin
passwd irpoadmin
# Вводим пароль: P@ssw0rd (2 раза)
```

---

### Шаг 4. Установка сервера управления «Кибер Бэкап»

Проверяем каталог сборки модулей, монтируем диск с дистрибутивом и запускаем инсталлятор:

```bash
ls -l /lib/modules/$(uname -r)/build

mount /dev/sr1 /mnt 2>/dev/null || mount /dev/sr0 /mnt

/mnt/cyberbackup_17.4.36200.x86_64 --skip-prereq-check --nodeps
```

В интерактивном псевдографическом меню выбираем следующие компоненты:
* `[*]` **Management Server**
* `[*]` **Agent for Linux**
* `[ ]` Bootable Media Builder
* `[ ]` Agent for CommuniGate Pro
* `[*]` **Agent for MySQL/MariaDB**

После завершения установки проверяем, что веб-сервер слушает порт `9877`:

```bash
ss -ltnp | grep 9877
```

---

### Шаг 5. Настройка службы MariaDB

Переводим MariaDB в режим сервера и перезапускаем:

```bash
control mysqld server
systemctl restart mysqld

ss -ltnp | grep 3306
```

## 3. Подготовка и установка Узла хранения на HQ-CLI

Перейдите на клиентскую машину **HQ-CLI** под пользователем `root`:

### Шаг 1. Обновление ядра и сборка модулей

```bash
apt-get update && apt-get install kernel-source-6.1 kernel-headers-modules-un-def gcc make kmod-sign -y

update-kernel -y

reboot
```

После перезагрузки проверяем версию ядра:

```bash
uname -r
```

---

### Шаг 2. Установка Storage Node

Монтируем диск и запускаем установщик:

```bash
mount /dev/sr0 /mnt 2>/dev/null || mount /dev/sr1 /mnt

/mnt/cyberbackup_17.4.36200.x86_64 --skip-prereq-check
```

В списке компонентов отмечаем:
* `[ ]` Management Server
* `[*]` **Agent for Linux**
* `[ ]` Bootable Media Builder
* `[*]` **Storage Node**

При запросе регистрации узла хранения указываем:
* **IP-адрес сервера управления**: `192.168.1.10`
* **Логин**: `root`
* **Пароль**: `toor`

---

## 4. Настройка организации, хранилища и планов в веб-панели

Открываем графический интерфейс (GUI) на **HQ-CLI** и переходим в браузере по адресу:

```text
https://hq-srv.au-team.irpo:9877
```
*(или `https://192.168.1.10:9877`)*

1. **Вход в систему**:
   * **Логин**: `root`
   * **Пароль**: `toor`
2. **Лицензия**: нажимаем **«Запустить пробную лицензию»** → **Подтвердить**.

---

### Шаг 1. Создание организации irpo и добавление администратора
1. Переходим в меню: **Настройки** → **Учетные записи** → **Организации** → **Создать отдел**.
2. Вводим название организации: **`irpo`**.
3. Выбираем созданную организацию `irpo` → нажимаем **Добавить учетную запись** → выбираем пользователя **`irpoadmin`**.

---

### Шаг 2. Создание Плана №1: Резервное копирование /etc (etc_backup)
1. В левом меню переходим: **Планы** → **Создать план**.
2. Нажимаем **Добавить устройство** → выбираем **`hq-srv`** → **Добавить**.
3. **Место сохранения**:
   * Выбираем **«Узел хранения»**.
   * Нажимаем **Путь** → **Создать папку** → вводим имя **`backup`** → **ГОТОВО**.
   * Указываем имя хранилища: **`backup_dir`**.
   * Учётные данные для доступа: `root` / `toor`.
4. **Выбор данных**:
   * Выбираем **«Файлы/папки»**.
   * Указываем системный каталог: **`/etc`**.
5. Меняем имя плана защиты на: **`etc_backup`**.
6. Нажимаем **Создать**.

---

### Шаг 3. Создание Плана №2: Резервное копирование БД MySQL (webdb_backup)
1. Нажимаем **Планы** → **Создать план**.
2. **Место сохранения**: выбираем созданное хранилище **`backup_dir`**.
3. **Выбор данных**:
   * Выбираем **«Резервное копирование приложения»** → **MySQL/MariaDB**.
   * Нажимаем **Добавить экземпляр** → вводим учетные данные `root` / `toor` → **Готово**.
4. Нажимаем **Добавить устройство** → выбираем **`hq-srv`** → **Добавить**.
5. Меняем имя плана защиты на: **`webdb_backup`**.
6. Нажимаем **Создать**.

---

### Шаг 4. Запуск резервного копирования
1. Переходим в раздел **Устройства**.
2. Поочерёдно нажимаем **«Создать резервную копию»** для планов:
   * **`etc_backup`**
   * **`webdb_backup`**
3. Дожидаемся завершения процесса копирования (процесс может занять продолжительное время).

---

## 5. Устранение проблем и освобождение места

### Решение ошибки отсутствия соединения с базой данных (webdb_backup)
Если план `webdb_backup` завершается с ошибкой авторизации MariaDB, выполните на сервере **HQ-SRV**:

```bash
systemctl stop mariadb

mysqld_safe --skip-grant-tables &

mysql -u root
```

В консоли MariaDB сбрасываем пароль пользователя `root`:
```sql
FLUSH PRIVILEGES;
ALTER USER 'root'@'localhost' IDENTIFIED BY 'toor';
FLUSH PRIVILEGES;
EXIT;
```

Перезапускаем штатный демон СУБД:
```bash
pkill mysqld
systemctl start mariadb
```
После этого повторно запускаем план `webdb_backup` в веб-панели.
