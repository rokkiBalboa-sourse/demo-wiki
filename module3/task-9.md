# Задание №9: Защита службы SSH с помощью Fail2ban на сервере HQ-SRV

В данном задании на сервере центрального офиса (**HQ-SRV**) настраивается система обнаружения и предотвращения атак **Fail2ban** для защиты службы безопасного удалённого доступа OpenSSH.

Система отслеживает системные журналы аутентификации. Если с одного IP-адреса фиксируется **3** неудачные попытки подбора пароля, адрес нарушителя автоматически блокируется межсетевым экраном на **1 минуту** (60 секунд).

> [!IMPORTANT] Где выполнять
> Все действия выполняются под пользователем `root` на сервере **HQ-SRV**.

---

## 1. Теоретическая справка: принцип работы Fail2ban

Утилита **Fail2ban** работает по следующему циклу:
1. Демон непрерывно анализирует системный лог авторизации (`/var/log/auth/messages`, `/var/log/messages` или журнал `systemd`).
2. По регулярным выражениям фильтра (`filter.d/sshd.conf`) выявляются строки с ошибками `Failed password` или `Invalid user`.
3. При достижении порога `maxretry = 3` в течение заданного окна времени `findtime` демон инициирует действие (`banaction`), добавляя временное блокирующее правило в подсистему пакетной фильтрации (nftables / iptables).
4. По истечении таймера `bantime = 60` (1 минута) блокирующее правило автоматически удаляется.

## 3. Установка и настройка Fail2ban на HQ-SRV

### Шаг 1. Установка пакета

```bash
apt-get update && apt-get install fail2ban -y
```

---

### Шаг 2. Создание файла локальной конфигурации /etc/fail2ban/jail.local

В ALT Linux параметры сервисов рекомендуется задавать в файле `jail.local`, чтобы они не перезаписывались при обновлении системы.

Создаём и открываем файл в редакторе:

```bash
vim /etc/fail2ban/jail.local
```

Вставляем конфигурацию с точными параметрами из экзаменационного задания:

```ini
[DEFAULT]
# Время бана: 1 минута (60 секунд)
bantime = 1m

# Окно отслеживания попыток
findtime = 10m

# Количество попыток до бана
maxretry = 3

# Бэкенд журналирования
backend = auto

[sshd]
enabled = true
# Нестандартный порт SSH согласно Модулю 1 Заданию 5:
port = 2026
filter = sshd
# Журнал авторизации в ALT Linux:
logpath = /var/log/auth/messages
maxretry = 3
bantime = 60
```

> [!NOTE] Если журнал авторизации пишется в /var/log/messages
> В зависимости от настроек rsyslog в ALT Linux события входа могут попадать в `/var/log/messages`. При необходимости укажите:
> ```ini
> logpath = /var/log/messages
> ```

Сохраняем файл (`Esc` → `:wq` → `Enter`).

---

### Шаг 3. Запуск и активация службы Fail2ban

Включаем автозапуск и перезапускаем демон:

```bash
systemctl enable --now fail2ban
systemctl restart fail2ban
```

---

## 4. Проверка статуса службы и активных правил

1. **Проверка общего состояния Fail2ban**:
   ```bash
   fail2ban-client ping
   # Ответ: Server replied: pong
   ```

2. **Просмотр состояния изолятора sshd**:
   ```bash
   fail2ban-client status sshd
   ```
   В выводе должно отображаться:
   ```text
   Status for the jail: sshd
   |- Filter
   |  |- Currently failed: 0
   |  |- Total failed:     0
   |  `- File list:        /var/log/auth/messages
   `- Actions
      |- Currently banned: 0
      |- Total banned:     0
      `- Banned IP list:
   ```

---

## 5. Тестирование блокировки с клиента HQ-CLI

Перейдите на клиентскую машину **HQ-CLI** под пользователем `root` или обычным пользователем:

1. **Инициируем 3 намеренно неверные попытки входа**:
   ```bash
   ssh -p 2026 baduser@192.168.1.10
   # Вводим любой неверный пароль 3 раза
   ```

2. **Проверяем результат бана**:
   При 4-й попытке подключение будет мгновенно сброшено или отклонено (`Connection refused` / `Connection timed out`).

3. **Проверяем на сервере HQ-SRV**:
   ```bash
   fail2ban-client status sshd
   ```
   В строке `Banned IP list:` появится IP-адрес рабочей станции: `192.168.2.10`.

4. **Проверка таймера разблокировки**:
   Подождите ровно 1 минуту (60 секунд) и повторите команду статуса — адрес `192.168.2.10` автоматически покинет список заблокированных, восстановив возможность легитимного входа.
